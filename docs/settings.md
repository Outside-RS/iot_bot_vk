# Настройки: .env и файлы конфигурации

Все секреты и настройки окружения живут в `vk-bot-search/.env`. Этого файла нет
в репозитории (он в `.gitignore`) и нет в Docker-образе (он в `.dockerignore`):
контейнер получает его при запуске через `env_file`.

Шаблон со всеми переменными — `vk-bot-search/.env.example`. Копируется так:

```bash
cp .env.example .env
```

---

## .env построчно

### База данных

```
DB_HOST=localhost
DB_PORT=5433
DB_NAME=postgres
DB_USER=postgres
DB_PASSWORD=
```

| Переменная | Значение | Если не задать |
|---|---|---|
| `DB_HOST` | адрес PostgreSQL. В docker-compose подменяется на `db` | подключение не удастся |
| `DB_PORT` | порт базы. Снаружи контейнера обычно 5433, внутри — 5432 | 5432 |
| `DB_NAME` | имя базы | подключение не удастся |
| `DB_USER` | пользователь базы | подключение не удастся |
| `DB_PASSWORD` | пароль пользователя | подключение не удастся |

`DB_PORT` используется и как порт, на котором база видна на самом компьютере
(в docker-compose она публикуется только на `127.0.0.1`).

### Админ-панель — обязательные

```
ADMIN_PASS=
SESSION_SECRET=
```

| Переменная | Значение |
|---|---|
| `ADMIN_PASS` | пароль входа в веб-панель. Один на всех администраторов |
| `SESSION_SECRET` | случайная строка, которой подписывается cookie сессии |

**Без этих двух бот не запустится** — остановится с сообщением в журнале. Так
сделано намеренно: пустой `ADMIN_PASS` раньше пускал в панель кого угодно, а
предсказуемый `SESSION_SECRET` позволяет подделать cookie администратора.

Сгенерировать секрет:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Не используйте для `ADMIN_PASS` свой рабочий или университетский пароль: он
лежит в файле открытым текстом.

### HTTPS (только для docker-compose)

```
PUBLIC_IP=
# TLS_MODE=acme
```

| Переменная | Значение | По умолчанию |
|---|---|---|
| `PUBLIC_IP` | публичный адрес, по которому открывается панель (IP сервера с frps). На него Caddy получает сертификат | обязательна, иначе `docker compose` откажется запускаться |
| `TLS_MODE` | `acme` — настоящий сертификат Let's Encrypt; `internal` — собственный сертификат Caddy для проверки на своём компьютере (браузер предупредит) | `acme` |

### GigaChat

```
GIGACHAT_AUTH_KEY=
GIGACHAT_SCOPE=GIGACHAT_API_PERS
```

Нужны только при первой установке: скрипты переносят ключ в настройки ИИ в базе,
дальше он меняется в панели и в `.env` не читается. `GIGACHAT_SCOPE` по
умолчанию `GIGACHAT_API_PERS` — режим для физических лиц.

**Сменить ключ правкой `.env` нельзя.** `migrate_update.js` переносит его в базу
только если там пусто, а в работе бот читает ключ из таблицы `app_settings` и
держит в памяти 30 секунд. На работающем боте новое значение из `.env` просто
не заметят. Меняйте в панели: «Обзор» → «Настройки ИИ». Подействует в течение
полуминуты, перезапуск не нужен. В `.env` ключ стоит обновить следом — он
пригодится, если базу когда-нибудь поднимут с нуля.

Та же логика у пароля базы: `DB_PASSWORD` из `.env` PostgreSQL читает только
при создании базы. Потом пароль живёт внутри неё, и правка `.env` приведёт лишь
к тому, что бот перестанет подключаться. Менять так:

```bash
docker compose exec db psql -U postgres -c "ALTER USER postgres WITH PASSWORD 'новый'"
```

и следом вписать его в `.env`, после чего пересоздать тех, кто им пользуется:
`docker compose up -d bot backup` (именно `up -d`, а не `restart` — переменные
попадают в контейнер при создании).

### Ollama (резервная локальная модель)

```
# OLLAMA_URL=http://127.0.0.1:11434
# OLLAMA_MODEL=qwen3:8b
```

Тоже только начальные значения, дальше настраивается в панели. В docker-compose
адрес подменяется на `http://host.docker.internal:11434`, чтобы контейнер достучался
до Ollama, установленной на самом компьютере.

### Локальное тестирование (на рабочем компьютере НЕ задавать)

```
# ALLOWED_GROUP_IDS=
# ENABLE_FRPC=true
```

| Переменная | Что делает |
|---|---|
| `ALLOWED_GROUP_IDS` | список номеров сообществ через запятую. Бот подключится **только** к ним, даже если в базе есть другие |
| `ENABLE_FRPC` | `true` — запускать `frpc.exe` вместе с ботом при работе без Docker |

`ALLOWED_GROUP_IDS` — защита от неприятной ситуации: в локальной базе могут
лежать рабочие сообщества с их токенами, и бот на вашем компьютере начнёт
перехватывать сообщения студентов у рабочего бота. Укажите здесь номер своего
тестового сообщества.

### Логи

```
# LOG_LEVEL=debug
# LOG_TIMEZONE=Asia/Yekaterinburg
# LOG_RETENTION_DAYS=14
# LOG_DIR=
# DB_SLOW_QUERY_MS=500
```

| Переменная | Значение | По умолчанию |
|---|---|---|
| `LOG_LEVEL` | `debug` (всё, включая подробности поиска), `info` (события), `warn`, `error` | `debug` |
| `LOG_TIMEZONE` | часовой пояс в записях журнала | `Asia/Yekaterinburg` |
| `LOG_RETENTION_DAYS` | сколько дней хранить файлы логов | 14 |
| `LOG_DIR` | папка файлов логов | `logs` рядом с проектом |
| `DB_SLOW_QUERY_MS` | запрос дольше этого числа миллисекунд попадёт в журнал как медленный | 500 |

### Резервные копии (только docker-compose)

```
# BACKUP_TIME=03:00
# BACKUP_KEEP_DAYS=14
BACKUP_SSH_HOST=
# BACKUP_SSH_USER=botbackup
# BACKUP_SSH_PORT=22
```

| Переменная | Значение | По умолчанию |
|---|---|---|
| `BACKUP_TIME` | во сколько делать ночную копию | 03:00 |
| `BACKUP_KEEP_DAYS` | сколько дней хранить копии на этом компьютере | 14 |
| `BACKUP_SSH_HOST` | сервер для второй копии. Пусто — копии только локально | пусто |
| `BACKUP_SSH_USER` | пользователь на сервере | `botbackup` |
| `BACKUP_SSH_PORT` | порт SSH | 22 |

На сервере копии хранятся 30 дней — это задано в скрипте приёма
`backup/receive-backup.sh`, не в `.env`.

## Остальные важные файлы

### frpc.toml — туннель до сервера

Тоже секрет (в нём токен), тоже не в репозитории. Образец — `frpc.toml.example`.

```toml
serverAddr = "94.103.86.240"   # адрес сервера с frps
serverPort = 7000
auth.method = "token"
auth.token = "..."             # тот же токен, что в frps.toml на сервере

webServer.addr = "127.0.0.1"   # интерфейс состояния туннеля, только внутри контейнера
webServer.port = 7400

[[proxies]]
name = "admin-https"
type = "tcp"
localIP = "caddy"              # внутрь контейнера Caddy
localPort = 443
remotePort = 443
transport.proxyProtocolVersion = "v2"   # передаёт настоящий IP посетителя

[[proxies]]
name = "admin-panel"
type = "tcp"
localIP = "caddy"
localPort = 80
remotePort = 80
```

На порту 80 передача IP намеренно не включена: сервер перенаправлений там
создаёт сам Caddy, заголовок он не разбирает и ответил бы ошибкой — а заодно
сломалась бы проверка Let's Encrypt.

Строки `webServer` нужны сторожу (см. ниже). Наружу этот интерфейс не выходит:
слушает `127.0.0.1` внутри контейнера, из сети к нему не достучаться.

### frpc-watchdog.sh — присмотр за туннелем

frpc после обрыва связи не всегда возвращается к жизни: бывает, что он до
бесконечности повторяет `i/o deadline reached` даже после того, как сеть
вернулась. Процесс при этом жив, и `restart: unless-stopped` не помогает —
Docker перезапускает только то, что упало. Выглядит это неочевидно: бот
отвечает студентам, а админка снаружи недоступна.

Поэтому контейнер `frpc` запускает не сам frpc, а этот скрипт. Он раз в минуту
спрашивает состояние у `webServer` и, если туннель не в состоянии `running`
три проверки подряд, завершает frpc — дальше контейнер поднимает Docker.

| Переменная | Значение | По умолчанию |
|---|---|---|
| `CHECK_INTERVAL` | как часто проверять, секунд | 60 |
| `FAILS_LIMIT` | сколько неудачных проверок подряд до перезапуска | 3 |
| `GRACE` | пауза перед первой проверкой, секунд | 30 |

Три проверки, а не одна: короткие обрывы frpc переживает сам, и перезапускать
контейнер из-за каждого моргания сети значит рвать рабочие соединения впустую.

Если строк `webServer` в конфиге нет, скрипт пишет об этом в журнал и запускает
frpc как обычно, без присмотра.

### Caddyfile — HTTPS

Получает и продлевает сертификат, передаёт запросы боту. Ключевые места:

- `default_sni {$PUBLIC_IP}` — при заходе по IP браузер не сообщает имя сайта,
  поэтому Caddy подсказывают, какой сертификат отдавать;
- `proxy_protocol` в `listener_wrappers` — принимает от frp настоящий IP
  посетителя. Без этого все запросы выглядели бы пришедшими от контейнера frpc:
  лимит попыток входа стал бы общим на всех, а в логах был бы один адрес;
- `import tls_{$TLS_MODE:acme}` — выбор между настоящим сертификатом и
  временным, в зависимости от `TLS_MODE`.

### docker-compose.yml — из чего состоит рабочая установка

| Контейнер | Зачем |
|---|---|
| `bot` | сам бот и веб-панель. Порт 3000 открыт только на самом компьютере |
| `db` | PostgreSQL. Порт тоже только локальный |
| `caddy` | HTTPS. Порты наружу не публикует: к нему приходит только туннель |
| `frpc` | туннель до сервера, под присмотром `frpc-watchdog.sh` |
| `backup` | ночные копии базы |

Тома: `postgres_data` (данные базы), `bot_logs` (логи), `caddy_data`
(сертификаты), `caddy_config`, `backup_keys` (ключ отправки копий). Папка
`backups` рядом с проектом — копии базы, их видно в обычном проводнике.

Первая строка файла — `name: vk-bot-search`. Это имя проекта, и от него зависят
имена томов: база лежит в `vk-bot-search_postgres_data`. По умолчанию Docker
берёт имя проекта из имени папки, поэтому без этой строки переименование или
перенос папки означали бы новый проект: пустые тома, бот с пустой базой, а
данные — в стороне под прежним именем. Строку лучше не трогать.

**`docker compose down -v` удаляет все тома** — базу, сертификат и ключ. На
рабочем компьютере эту команду выполнять нельзя.

### Dockerfile — образ бота

`node:22-alpine`, зависимости ставятся через `npm ci --omit=dev` (ровно те
версии, что записаны в `package-lock.json`), запуск от пользователя `node`, а
не от root. Секреты в образ не попадают — см. `.dockerignore`.

### .dockerignore и .gitignore

`.dockerignore` не пускает в образ `.env`, `frpc.toml`, `node_modules`, логи,
копии базы и тесты. `.gitignore` не пускает в репозиторий `.env`, `frpc.toml`,
логи (там сообщения студентов), резервные копии (там персональные данные) и
рабочие заметки.

### init.sql

Одна строка: `CREATE EXTENSION IF NOT EXISTS pg_trgm;`. PostgreSQL в
docker-compose выполняет её при первом создании базы — расширение нужно для
поиска по триграммам.

## Смена пароля панели

Пароль хранится в `.env`, в переменной `ADMIN_PASS`.

1. Откройте `.env` и замените значение:

```
ADMIN_PASS=новый-пароль
```

2. Примените. **В Docker простого `restart` недостаточно**: переменные окружения
   попадают в контейнер при его создании, и перезапуск оставит старый пароль.
   Нужно пересоздать контейнер:

```bash
docker compose up -d bot
```

Если бот запущен без Docker — остановите `node index.js` и запустите снова.

3. При необходимости выкиньте всех, кто уже вошёл. Смена пароля сама по себе
   сессии не обрывает: администратор с открытой панелью останется внутри до
   истечения сессии (сутки). Чтобы разлогинить всех сразу:

```bash
docker compose exec db psql -U postgres -c "DELETE FROM session"
```

Пароль общий для всех администраторов, поэтому после смены раздайте его заново.

## Смена кода доступа администратора в боте

Это другое: код вводится в самом боте и даёт человеку роль администратора.
Меняется в панели, раздел «Администраторы».

1. Создайте новый код с именем нужного человека.
2. Попросите его перезайти: в боте «👤 Профиль» → «🚪 Выйти из аккаунта», затем
   написать любое сообщение и ввести новый код.
3. Удалите старый код.

Важно: **удаление кода не отбирает роль** у того, кто уже вошёл по нему — роль
записана в его профиле. Если нужно именно отобрать доступ, удалите человека в
разделе «Пользователи»: при следующем сообщении боту он пройдёт регистрацию
заново и без действующего кода администратором не станет.

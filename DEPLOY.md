# Перенос и обновление бота на рабочем компьютере

Инструкция для компьютера, на котором бот работает постоянно (ПК в вузе, Windows).
Порядок рассчитан на то, что там уже запущена старая версия.

Схема после переноса:

```
Браузер администратора
        |  https://<IP VPS>
        v
   VPS: frps (порты 80, 443, 7000)
        |  туннель frp
        v
ПК в вузе, docker compose:
   frpc -> caddy (HTTPS) -> bot -> db
                            backup -> копии базы: сюда и на VPS
   Ollama стоит на самом ПК, вне docker
```

Что нужно под рукой: пароль от админки, токен frps (он уже есть в `frpc.toml` на этом ПК),
SSH-доступ к VPS со своего личного компьютера.

Все команды выполняются в папке проекта — там, где лежит `docker-compose.yml`.
Они одинаковы для Git Bash и PowerShell.

---

## 1. Подготовка, пока старая версия работает

### 1.1. Резервная копия базы

```bash
docker compose exec -T db sh -c "pg_dump -U postgres -d postgres | gzip > /tmp/before-update.sql.gz"
```

```bash
docker cp "$(docker compose ps -q db):/tmp/before-update.sql.gz" ./before-update.sql.gz
```

Проверьте, что файл `before-update.sql.gz` появился и весит не ноль. Это точка возврата:
из него база восстанавливается целиком (раздел 8).

### 1.2. Запомнить текущую версию кода

```bash
git rev-parse --short HEAD
```

Запишите номер. К нему можно вернуться, если что-то пойдёт не так.

### 1.3. Проверить `.env`

Откройте `.env` в папке проекта. Должны быть заполнены:

| Переменная | Что это | Если её нет |
|---|---|---|
| `DB_USER`, `DB_PASSWORD`, `DB_NAME` | доступ к базе | оставить как было |
| `ADMIN_PASS` | пароль входа в веб-админку | придумать |
| `SESSION_SECRET` | подпись cookie сессии | **новое требование** — без него бот не запустится |

Если `SESSION_SECRET` нет, создайте случайную строку и впишите её:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Добавьте в `.env` ещё три строки:

```
PUBLIC_IP=94.103.86.240
BACKUP_SSH_HOST=94.103.86.240
LOG_TIMEZONE=Asia/Yekaterinburg
```

`PUBLIC_IP` — адрес, по которому открывается админка; на него Caddy получает сертификат.
`BACKUP_SSH_HOST` — куда отправлять копии базы; если оставить пусто, копии будут только
на этом компьютере.

Полный список переменных с пояснениями — в `vk-bot-search/.env.example`.
Сам `.env` в репозиторий не попадает и при обновлении кода не перезаписывается.

## 2. Обновление кода

Если папка проекта — клон репозитория:

```bash
git pull
```

Если нет — скопируйте свежую версию папки с заменой файлов, **сохранив** `.env` и `frpc.toml`:
их нет в репозитории, и потерять их нельзя.

---

## 3. Настройка туннеля

Откройте `frpc.toml`. Строки `serverAddr`, `serverPort` и `auth.token` оставьте свои,
а все блоки `[[proxies]]` замените на блоки из `frpc.toml.example`.

Должно получиться два прокси: `admin-https` (порт 443, с передачей IP посетителя)
и `admin-panel` (порт 80, без передачи IP — иначе Let's Encrypt не сможет проверить сервер).

На VPS настраивать ничего не нужно: frps работает в режиме сети host и без ограничений
по портам, файрвол не включён, порт 443 свободен — проверено 16.09.2026.

---

## 4. Запуск

```bash
docker compose up -d --build
```

Первый раз это займёт несколько минут: скачиваются образы Caddy и PostgreSQL,
собираются образы бота и контейнера копий. Нужен интернет.

Затем обновите базу до текущей версии кода:

```bash
docker compose exec bot node migrate_update.js
```

Скрипт идемпотентный: добавляет недостающие колонки и таблицы, данные не трогает,
запускать можно повторно.

**Если база пустая** (бот ставится на новый компьютер с нуля), эта команда завершится
ошибкой `relation "ai_queue" does not exist` — обновлять ещё нечего. Сначала создайте
схему, а потом повторите обновление:

```bash
docker compose exec bot node reset_db.js
```

Скрипт спросит подтверждение: нужно ввести имя базы. **На работающем боте его запускать
нельзя** — он удаляет все таблицы вместе с данными.

## 5. Проверка

### 5.1. Контейнеры

```bash
docker compose ps
```

Подняты должны быть пять: `bot`, `db`, `caddy`, `frpc`, `backup`.

### 5.2. Сертификат HTTPS

```bash
docker compose logs caddy
```

Нужна строка `certificate obtained successfully` со ссылкой на `acme-v02.api.letsencrypt.org`.
После этого откройте `https://94.103.86.240` — браузер не должен ругаться на сертификат.

Если сертификат не выдан, причина будет в этом же логе. Обычно это закрытый порт на VPS
или сеть вуза, которая не пускает к серверам Let's Encrypt. Временное решение — дописать
в `.env` строку `TLS_MODE=internal` и выполнить `docker compose up -d caddy`: HTTPS заработает,
но браузер будет предупреждать о недоверенном сертификате.

### 5.3. Бот

```bash
docker compose logs bot
```

Ожидаются строки `[DB] Подключено к базе`, `[BOT] Бот запущен` для каждого сообщества,
`[WORKER] AI Queue worker запущен`.

### 5.4. Резервные копии

```bash
docker compose logs backup
```

В логе будет строка вида:

```
restrict,command="/usr/local/bin/receive-backup" ssh-ed25519 AAAA... vkbot-backup
```

Скопируйте её целиком — она понадобится в разделе 6.

### 5.5. Админка

Откройте `https://94.103.86.240`, войдите паролем из `ADMIN_PASS` и проверьте:

1. «Группы VK» → кнопка «↻ Сверить все с VK»: курсы сообществ подтянутся из их названий.
2. Личные коды администраторов вместо общего `ADMIN-MAIN` — см. раздел 5.7.
3. На главной появится карточка «Резервная копия» с датой последней копии.

### 5.6. Бот в VK

Напишите боту из тестового сообщества: задайте вопрос, дождитесь ответа ИИ, нажмите
«Передать администратору» и убедитесь, что вопрос дошёл до администратора.

### 5.7. Личные коды администраторов

Пока в базе есть общий код `ADMIN-MAIN`, роль администратора в боте может получить любой,
кто его введёт: код лежит в исходниках проекта. На главной админки об этом висит красный
баннер. Заменять его на личные коды нужно в таком порядке:

1. На странице «Администраторы» заведите каждому свой код и впишите его имя. Имя из кода
   попадает в профиль и подставляется в сообщения: «Вопрос #12 принят в работу.
   Администратор: Алёна».
2. Попросите администраторов перезайти под своим кодом: в боте «👤 Профиль» →
   «🚪 Выйти из аккаунта», затем написать боту любое сообщение и ввести новый код.
   Тех, кто не перезашёл, удалите на странице «Пользователи» — при следующем сообщении
   боту они пройдут регистрацию заново.
3. Только после этого удалите код `ADMIN-MAIN`.

**Роль хранится в профиле пользователя, а не в коде.** Если просто удалить `ADMIN-MAIN`,
все, кто успел войти по нему, останутся администраторами с именем «Администратор» —
и в уведомлениях будет не видно, кто взял вопрос.

## 6. Резервные копии на VPS

Делается один раз. На VPS уже созданы пользователь `botbackup`, его папка и скрипт приёма
`/usr/local/bin/receive-backup`. Осталось разрешить ключ, который создал контейнер `backup`
(строка из пункта 5.4).

Зайдите на VPS со своего личного компьютера и выполните:

```bash
cat >> /home/botbackup/.ssh/authorized_keys
```

Вставьте строку, нажмите Enter, затем Ctrl+D. После этого:

```bash
chmod 600 /home/botbackup/.ssh/authorized_keys
chown botbackup:botbackup /home/botbackup/.ssh/authorized_keys
```

Проверьте отправку с ПК в вузе:

```bash
docker compose run --rm backup now
```

Ожидаемый ответ: `Копия готова`, затем `принято: ...` и `Копия отправлена на сервер`.

Дальше копии делаются каждую ночь в 03:00: 14 дней хранятся в папке `backups` рядом
с проектом, 30 дней — на VPS.

## 7. Чтобы бот работал без присмотра

Главный риск — не сбой программы, а перезагрузка Windows. Docker Desktop запускается только
после входа пользователя в систему, поэтому после перезагрузки из-за обновлений бот
не поднимется, пока кто-то не войдёт.

1. **Автоматический вход в Windows.** Win+R → `netplwiz` → снять галочку «Требовать ввод
   имени пользователя и пароля» → ввести пароль учётной записи. Если галочки нет, включить
   её видимость: Win+R → `regedit` →
   `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\PasswordLess\Device` →
   параметр `DevicePasswordLessBuildVersion` = 0.
2. **Автозапуск Docker Desktop.** Настройки Docker Desktop → General →
   «Start Docker Desktop when you sign in».
3. **Не уходить в спящий режим.** Параметры → Система → Питание → «Сон» → «Никогда».
   Либо в командной строке от администратора:
   ```
   powercfg /change standby-timeout-ac 0
   powercfg /change hibernate-timeout-ac 0
   ```
4. **Включение после пропадания питания.** В BIOS найти «Restore on AC Power Loss»
   (или «After Power Failure») и выставить «Power On».
5. **Время обновлений Windows.** Параметры → Центр обновления → Период активности:
   выставить рабочие часы, чтобы перезагрузки приходились на ночь.

Контейнеры поднимаются сами: у всех стоит `restart: unless-stopped`. Ollama на Windows
стартует вместе с входом в систему.

Обновлять программы не нужно: версии зафиксированы, сертификат Caddy продлевает сам.
Раз в год можно обновить Caddy:

```bash
docker compose pull caddy && docker compose up -d caddy
```

## 8. Если что-то пошло не так

### Откат кода

```bash
git checkout НОМЕР_ВЕРСИИ_ИЗ_ПУНКТА_1.2
docker compose up -d --build
```

### Восстановление базы

Бот останавливается, текущая база переименовывается в `postgres_old` — её можно удалить
позже, когда убедитесь, что всё в порядке.

Ниже `postgres` — имя базы; если в `.env` переменная `DB_NAME` другая, подставьте своё.

```bash
docker compose stop bot backup
```

```bash
docker cp ./before-update.sql.gz "$(docker compose ps -q db):/tmp/restore.sql.gz"
```

Отключить оставшиеся подключения к базе — иначе переименовать её не получится:

```bash
docker compose exec -T db psql -U postgres -d template1 -c "SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE datname='postgres' AND pid <> pg_backend_pid()"
```

Переименовать старую базу и создать пустую. Команды выполняются с подключением
к служебной базе `template1`: PostgreSQL не разрешает переименовать базу,
к которой подключён сам, — без этого всё сорвётся на первом же шаге.

```bash
docker compose exec -T db psql -U postgres -d template1 -c "ALTER DATABASE postgres RENAME TO postgres_old"
docker compose exec -T db psql -U postgres -d template1 -c "CREATE DATABASE postgres"
```

Залить копию и запустить бота обратно:

```bash
docker compose exec -T db sh -c "gunzip -c /tmp/restore.sql.gz | psql -U postgres -q -d postgres"
docker compose start bot backup
```

Ошибок при заливке быть не должно. Если их много и они вида
`relation ... already exists` — значит, база не была пустой, и восстановление
нужно начинать заново с шага переименования.

Проверьте, что данные на месте:

```bash
docker compose exec -T db psql -U postgres -c "SELECT count(*) FROM faq"
```

Когда убедитесь, что всё работает, удалите старую базу:

```bash
docker compose exec -T db psql -U postgres -d template1 -c "DROP DATABASE postgres_old"
```

Так же восстанавливается любая ночная копия из папки `backups` или с VPS
(`/home/botbackup/backups`, скачивается командой `scp`).

### Проверить копию, не трогая рабочую базу

```bash
docker cp ./backups/ИМЯ_ФАЙЛА.sql.gz "$(docker compose ps -q db):/tmp/check.sql.gz"
docker compose exec -T db psql -U postgres -c "CREATE DATABASE restore_check"
docker compose exec -T db sh -c "gunzip -c /tmp/check.sql.gz | psql -U postgres -q -d restore_check"
docker compose exec -T db psql -U postgres -d restore_check -c "SELECT count(*) FROM faq"
```

Удалить проверочную базу:

```bash
docker compose exec -T db psql -U postgres -c "DROP DATABASE restore_check"
```

## 9. Что где лежит

| Что | Где |
|---|---|
| Настройки и пароли | `.env` в папке проекта (в репозиторий не попадает) |
| Токен туннеля | `frpc.toml` там же (в репозиторий не попадает) |
| Копии базы | папка `backups` рядом с проектом и `/home/botbackup/backups` на VPS |
| Логи бота | том Docker `bot_logs`; скачиваются в админке на странице «Логи» |
| Сертификат HTTPS | том Docker `caddy_data` |
| Ключ отправки копий | том Docker `backup_keys` |
| Данные базы | том Docker `postgres_data` |

Тома Docker переживают пересборку контейнеров, но удаляются командой `docker compose down -v`.
На рабочем компьютере эту команду выполнять нельзя: она сотрёт базу, сертификат и ключ.

## 10. Повседневные команды

| Задача | Команда |
|---|---|
| Обновить бота после изменений в коде | `git pull && docker compose up -d --build` |
| Обновить базу под новую версию кода | `docker compose exec bot node migrate_update.js` |
| Посмотреть, что происходит | `docker compose logs -f bot` |
| Сделать копию базы прямо сейчас | `docker compose run --rm backup now` |
| Перезапустить всё | `docker compose restart` |
| Остановить | `docker compose stop` |

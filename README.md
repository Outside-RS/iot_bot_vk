# Бот поддержки студентов ИОТ

Чат-бот ВКонтакте, который отвечает на вопросы студентов института и передаёт
администраторам то, на что не смог ответить сам. К боту прилагается веб-панель
управления: база знаний, обращения, сообщества, пользователи, рассылка, логи.

Стек: Node.js 22, PostgreSQL 15, Express 5, EJS, vk-io, Docker Compose.

**Подробная документация — в папке [docs/](docs/):** устройство проекта и разбор
файлов, работа бота в сообществе, веб-панель, база данных, настройки, руководство
для тьюторов и разбор типовых задач для тех, кто продолжит разработку. Отдельно —
[что делать, если бот не отвечает](docs/restart.md): для тех, кто окажется рядом
с компьютером, когда он выключится.

## Как бот отвечает на вопрос

Три уровня, по возрастанию стоимости ответа.

**1. База знаний.** Поиск по вопросам и ключевым словам: полнотекстовый поиск
PostgreSQL (словарь `russian`) плюс сравнение по триграммам `pg_trgm` — второе
ловит опечатки и формулировки «своими словами». Оценка совпадения складывается
из обеих частей. Если у лучшего совпадения оценка от 0.15 — бот сразу показывает
готовый ответ; если совпадений несколько и явного лидера нет — предлагает выбрать
из списка.

**2. ИИ-ассистент.** Когда уверенного ответа в базе нет, вопрос уходит в очередь
к ИИ. Найденные записи базы знаний передаются модели как контекст, но только те,
у которых оценка от 0.1 — иначе в модель уходит шум и она начинает додумывать.
Основной провайдер — GigaChat, резервный — локальная Ollama.

**3. Живой администратор.** Если ответа нет и у ИИ, студент нажимает кнопку и
создаёт обращение. Администраторы получают уведомление в ВКонтакте и отвечают
через бота. Из завершённого диалога можно одной кнопкой сделать новую запись
базы знаний — дальше бот отвечает на такой вопрос сам.

Обращение принадлежит тому курсовому сообществу, в котором задан вопрос, и
ведётся только оттуда: ответить студенту бот может лишь через сообщество, куда
тот писал.

### Что удерживает ИИ от выдумок

- **Проверка контактов.** Почта, телефоны, ссылки и аудитории из ответа модели
  сверяются со всей базой знаний. Неподтверждённые заменяются пометкой
  «уточните у администратора» (`fact_guard.js`). Это ловит главную проблему
  справочного бота: правдоподобный, но выдуманный адрес почты деканата.
- **Маршрут к человеку.** Если модель сама признала, что данных нет, к ответу
  дописывается приглашение передать вопрос администратору (`answer_policy.js`).
- **Промпт по разделам** с явным запретом отвечать по памяти, когда контекста нет.

### Очередь запросов к ИИ

Очередь живёт в таблице `ai_queue`, а не в памяти процесса: перезапуск бота не
теряет вопросы. Воркер берёт задачи через `FOR UPDATE SKIP LOCKED`, поэтому
параллельные обработчики не возьмут одну задачу дважды. Занятость провайдера не
считается сбоем задачи — иначе второй человек в очереди получал бы «системную
ошибку» вместо ответа. Задача, которая стабильно валит обработку, снимается
после двух попыток, студент получает объяснение.

У GigaChat во freemium-режиме у каждого класса моделей своя независимая квота.
Бот считает израсходованные токены по классам и при исчерпании одного переходит
к следующему (`ai_models.js`), а не падает на резервную модель.

## Курс студента и перевод на следующий

Источник истины — курсовое сообщество ВКонтакте, из которого пишет студент:
вступление в него модерируется, а номер группы студент вводит сам и может
ошибиться. Курс берётся из названия сообщества: «Второй курс …» → 2,
«… Архив 25/26» → выпуск (`courses.js`).

Бот сверяет названия сообществ с ВКонтакте 1 августа и 1 сентября в 03:00
(`group_sync.js`). Когда сообщество переименовали со «Второго курса» на «Третий»,
всем его студентам поднимается курс в номере группы; когда сообщество ушло в
архив — студенты отмечаются выпускниками. Если название изменилось непонятно
(например, курс «уменьшился»), бот ничего не трогает и пишет об этом в журнал.
Сверку можно запустить вручную кнопкой в панели.

## Веб-панель

Боковое меню на компьютере, выезжающая шторка на телефоне.

| Раздел | Что можно |
|---|---|
| **Обзор** | обращения, запущенные боты, состояние резервных копий, настройки ИИ и расход токенов |
| **База знаний** | поиск по вопросам и ответам, фильтр по категориям, сортировка, импорт и экспорт JSON |
| **Администраторы** | коды доступа: по ним человек становится администратором в боте |
| **Группы VK** | подключённые сообщества, курс каждого, сверка названий с ВКонтакте |
| **Пользователи** | поиск и фильтры, перевод на следующий курс, отметка выпускников |
| **Рассылка** | сообщение всем, студентам, администраторам или одной группе |
| **Жалобы** | отзывы студентов о работе бота, со статусами |
| **Логи** | журнал в реальном времени с фильтрами по уровню и подсистеме, скачивание файла за день |

Списки выводятся постранично: страницы, которые загружали всю таблицу целиком,
на реальной базе открывались бы секундами.

## Безопасность

- Вход в панель: пароль сравнивается за постоянное время, 10 попыток за 15 минут,
  сессия пересоздаётся после входа и хранится в PostgreSQL.
- CSRF-токен на всех изменяющих операциях, CSP с запретом обработчиков в атрибутах.
- Весь вывод экранируется; журнал логов собирается из текстовых узлов — сообщение
  студента вида `<img onerror=…>` не выполнится у администратора.
- Все запросы к базе параметризованные; поле сортировки берётся из закрытого списка.
- Подбор кода администратора в боте: 5 попыток за 15 минут.
- Действия с обращением доступны только его участникам, команды из кнопок
  проверяются по роли — подделанный payload ничего не даёт.
- HTTPS с автоматическим продлением сертификата (см. ниже).

## Как устроено развёртывание

```
Браузер администратора
        │  https://<IP>
        ▼
   VPS: frps — только ретранслятор трафика
        │  туннель frp
        ▼
Рабочий компьютер, docker compose:
   frpc → caddy (HTTPS) → bot → db
                          backup → копии базы: локально и на VPS
   Ollama — на самом компьютере, вне docker
```

Бот общается с ВКонтакте исходящими запросами, поэтому публичный адрес нужен
только для веб-панели. Если VPS пропадёт, студенты этого не заметят.

**HTTPS без домена.** Сертификат Let's Encrypt выдаётся прямо на IP-адрес
(профиль shortlived, доступен с января 2026), Caddy продлевает его сам каждые
2–3 дня. Туннель передаёт трафик зашифрованным: ключ хранится рядом с ботом,
VPS содержимое запросов не видит.

**Резервные копии.** Контейнер `backup` раз в сутки снимает дамп базы: 14 дней
хранится рядом с проектом, 30 дней — на VPS. Ключ отправки ограничен на сервере
одной разрешённой командой — принять файл. На главной панели видно дату
последней копии, и она краснеет, если копий давно не было.

Пошаговый перенос, проверка после запуска, автономная работа под Windows,
откат и восстановление базы — в **[DEPLOY.md](DEPLOY.md)**.

## Запуск для разработки

Нужны Node.js 22 и PostgreSQL 15 (проще — в Docker).

```bash
docker run -d --name vk-bot-db -p 5433:5432 -e POSTGRES_PASSWORD=пароль postgres:15-alpine
```

```bash
cd vk-bot-search
npm install
cp .env.example .env    # заполнить DB_*, ADMIN_PASS, SESSION_SECRET
node reset_db.js        # создаст схему и загрузит faq_data.json
node index.js
```

Панель — на `http://localhost:3000`, бот подключится к сообществам из таблицы
`vk_groups`. Для локальной работы укажите в `.env` `ALLOWED_GROUP_IDS` со своим
тестовым сообществом: иначе бот подключится ко всем сообществам из базы, включая
рабочие, и начнёт перехватывать сообщения студентов.

Полностью в Docker (бот, база, HTTPS, копии) — понадобится `PUBLIC_IP` в `.env`,
а для проверки на своём компьютере ещё и `TLS_MODE=internal`, чтобы Caddy выдал
временный сертификат вместо настоящего:

```bash
docker compose up -d --build
```

## Скрипты

| Скрипт | Назначение |
|---|---|
| `node index.js` | запуск бота и веб-панели |
| `node reset_db.js` | создать схему с нуля — **удаляет все таблицы**, спрашивает подтверждение |
| `node migrate_update.js` | обновить существующую базу под текущий код, идемпотентно |
| `node update_faq.js` | дополнить базу знаний из `faq_data.json`; `--replace` — заменить её целиком |
| `node remind_registration.js` | напомнить тем, кто не завершил регистрацию; без `--send` только показывает список |
| `npm test` | 171 тест, нужна PostgreSQL |
| `node tests/eval_answers.js` | прогон контрольных вопросов через живую модель (расходует токены) |

## Структура

```
vk-bot-search/
├── index.js            запуск: веб-панель, подключение сообществ, остановка по сигналу
├── bot.js              диалоги с пользователем: состояния, кнопки, обращения
├── ai_worker.js        очередь к ИИ: выбор провайдера, повторы, отправка ответа
├── ai_service.js       запросы к GigaChat и Ollama, промпт, учёт токенов
├── ai_models.js        классы моделей GigaChat и их квоты
├── faq_search.js       поиск по базе знаний и контекст для ИИ
├── fact_guard.js       сверка контактов в ответе модели с базой знаний
├── answer_policy.js    маршрут к администратору, когда ответа нет
├── courses.js          курс из названия сообщества
├── group_sync.js       сверка названий с ВКонтакте, перевод на следующий курс
├── logger.js           уровни, теги, файлы по дням, местное время
├── database.js         пул соединений, устойчивость к обрыву связи
├── routes/admin.js     маршруты веб-панели
├── views/              страницы панели (EJS)
├── public/             стили и скрипты панели
├── backup/             контейнер резервных копий и приём на сервере
├── tests/              тесты
├── Caddyfile           HTTPS
├── frpc-watchdog.sh    присмотр за туннелем: перезапуск, если frpc завис
└── docker-compose.yml  bot, db, caddy, frpc, backup
```

### Таблицы

`users` — студенты и администраторы, состояние диалога, курс, настройки уведомлений ·
`vk_groups` — сообщества, токены, курс · `operator_codes` — коды доступа администраторов ·
`faq` — база знаний с индексом полнотекстового поиска · `tickets` и `messages` — обращения
и переписка по ним · `ai_queue` — очередь к ИИ · `ai_usage` — расход токенов по классам
моделей · `app_settings` — настройки ИИ · `feedback` — отзывы о работе бота ·
`session` — сессии панели.

## Тесты

```bash
cd vk-bot-search
npm test
```

171 тест: разбор ответов модели и промпт, поиск по базе знаний и пороги,
проверка выдуманных контактов, логика очереди ИИ, устойчивость к падению базы,
курсы и перевод, логирование, ограничения ВКонтакте на длину сообщений и
клавиатуру, права на действия в боте, разделение обращений по курсовым
сообществам и выход из любого шага диалога.

Нужна запущенная PostgreSQL. Тесты пишут в ту базу, которая указана в `.env`,
поэтому заводите под них отдельную — либо временно меняйте `DB_NAME` в `.env`,
либо задавайте её прямо в команде (Git Bash):

```bash
DB_NAME=vk_bot_test npm test
```
